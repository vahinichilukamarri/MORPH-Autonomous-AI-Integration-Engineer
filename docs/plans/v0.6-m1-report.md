# v0.6 M1 report: policy core

Scope: the pure policy layer. No database, no MCP server, no model, no network. Numbers are counts from
a local run on this machine (Windows 11, Python 3.12.6); the CI result is in the reply that accompanies
the push that contains this report.

## What exists (`backend/app/policy/`)

| Module | Role |
|---|---|
| `models.py` | strict (`extra=forbid`, frozen) policy file, request context, decision record, enums |
| `canonical.py` | canonical JSON and SHA-256 |
| `toolspec.py` | the 13 tools (8 read-only, 5 with side effects), strict argument models, the forbidden-name pattern |
| `floor.py` | floor rules F01 to F10 in code; argument inspection (URLs, paths); policy-versus-floor check; result size and test-data rules |
| `loader.py` | `yaml.safe_load` with duplicate keys refused, 64 KB cap, validation, floor check, canonical hash, `policy.lock`, `versions.json`, change classification |
| `evaluate.py` | floor first, then session limits, then rules: deny, then needs-approval, then allow, then default deny |
| `redact.py` | known-value redaction plus secret-shaped patterns plus a narrow high-entropy rule |
| `check.py` | `python -m app.policy.check`, run in CI |
| `backend/policy/` | `morph-policy-v1.yaml` (7 rules, limits 12 model calls, 40 sandbox runs, 200,000 result bytes), `policy.lock`, `versions.json` |

The evaluator reads only a `CallContext` the server derives: the tool, its effects, the role, the target's
`environment` and `data_class`, whether the model is involved, argument facts (a URL is present, a path
escapes the root), the approval check result and the session counters. It has no free-text field, and a
test asserts the field set, so a decision cannot depend on text an attacker controls.

## How the plan's M1 requirements are met

* **Loader** uses `safe_load` into a strict model; a Python tag, an unknown key, a duplicate key, a bad
  decision, an unknown tool name and an oversize file are each refused (10 parametrized cases).
* **Floor in code** (F01 execute only on a mock, F02 no URL, F03 path inside root including symlinks, F04
  known tools, F05 no forbidden capability, F06 result size, F07 redaction, F08 test data withheld,
  F09 an approval never overrides a denial, F10 limit ceilings). A policy that would let code run on a
  non-mock target, exceeds a ceiling or names an unknown tool is **rejected at load**.
* **Evaluator** precedence and default deny are tested, as are budgets, approvals in every invalid state
  (7 states), determinism, and replay from the recorded inputs.
* **Redaction**: 4 sentinel values (including a database URL and its password) and 12 secret-shaped strings
  the redactor was not told about are removed; 8 near misses (long identifiers, a run of one letter,
  prose, a localhost URL, words starting with `sk`) are left alone; redaction is idempotent.
* **Lock and versions**: a lock mismatch refuses to start; a released version that changes is a problem;
  an unlisted file is a problem; a version that loosens without declaring it is a problem; changes are
  classified conservatively (5 cases plus the removed-allow-rule case).
* **Controls enforced by a meta-test**: 18 rule ids (7 policy rules, the session-limit rule L01, 10 floor
  rules) each have a positive and a negative control in `tests/policy/controls.py`. The meta-test fails if
  a rule exists without controls, if a control names a rule that does not exist, or if a control does not
  behave. That is 36 control checks.
* `types-pyyaml` is in the backend dev group, and `pyyaml` is a direct dependency since M0.

## Tests (local)

`tests/policy`: 182 passed, 1 skipped. The skip is a file symlink pointing outside the root: Windows without
the privilege cannot create one. The directory case (a junction here, a symlink on Linux) ran and passed.
CI on Linux runs both. `ruff check`, `ruff format --check` and `mypy` strict are clean for the backend.

## Deviations and things to know

* **URL allowlist cut.** The plan allowed a policy allowlist of URL hosts (empty in v1). No tool fetches a
  URL in v0.6, so an allowlist would be a feature with no user. The floor denies every URL argument. This is
  a tightening; if a later version needs a fetching tool it needs a new floor rule and a new version.
* **The hash is of the parsed model**, not the file bytes: comments and key order do not change it, and a
  test shows that. An edit that changes meaning always changes it.
* **The lock guards drift, not repository write access**, as the plan states: someone who can edit the
  repository can change a policy file and the lock together.
* **Symlink and junction coverage on Windows** depends on the host; see the skip above.
* **Long-run redaction rule.** To avoid the v0.4 `SECRET_LITERAL` false positive (benign long identifiers),
  a long run is redacted only if it mixes digits, lower and upper case and has at least 4.0 bits per
  character of entropy. This is a heuristic with a stated threshold; a secret made only of lower-case
  letters would not be caught by this rule (it would be caught by the known-value layer if configured).
