## Findings and fixes (disclosed)

* **Three redaction leaks.** The first run of the redaction corpus failed 3 of 22: the approver token
  and the database password reached stored audit rows (`R-AUDIT-approver`, `R-AUDIT-password`) and the
  REST audit response (`R-REST-audit`). The audit log redacted only the secrets it was given and the
  gateway and the REST dependency gave it none. Fixed at the source with one shared list of configured
  secrets (`app/policy/secrets.py`) used by the server, the gateway's audit notes and the REST route.
  Rerun: 22 of 22.
* **Kit defect, not a log defect.** Two forged-event tests inserted the same constant row hash and the
  table's unique constraint refused the second. Each forged event now derives its own hash.
* **Report generator**: a dataclass field named like the module it annotated made the generator crash;
  result types are now imported by name.
* **Test isolation**: `tests/repair/test_graph.py` selected gate results across the whole database,
  so rows committed by the new gateway tests changed its result in a full run. The query is now scoped
  to the run under test. The assertion is unchanged.

## Limits

* Hand-written cases that test our rules; they are not an adversarial search and not a security proof.
* The scripted adversary follows fixed instructions; real agents differ. Nothing here measures a model.
* The symlink-to-a-file case uses a directory junction on Windows without the symlink privilege; it
  exercises the same resolution check.
* Removing the last events of an audit chain is not detected; the policy lock guards against drift, not
  against someone with write access to the repository.
