# v0.7-ui plan

Branch `ui/v0.7`, work under `frontend/` (plus this plan, `docs/img/`, the README UI section and the
frontend CI job). No backend, bench or sandbox change, no model call, no tag, no deploy.

## Decisions

1. **Two modes, one component set.** `VITE_MORPH_MODE=demo` (the default build) runs entirely in the
   browser from generated static JSON; `live` reads the existing REST API through a typed client. Both
   go through one `DataSource` interface (`src/api/source.ts`).
2. **Demo data is generated, never typed in.** `frontend/scripts/build-demo-data.ts` reads only committed
   files (`bench/results/codegen-v0.4/`, `bench/results/repair-v0.5/fixed/`, `bench/replays/codegen/`,
   `bench/replays/repair/fixed/`, `bench/replays/crm_customer_to_support_user.expected.json`) and writes
   `src/data/demo.generated.json` and `src/data/replies.generated.json`, each with the SHA-256 of its
   sources. A Vitest drift test regenerates both in memory and fails on any difference. UI copy contains
   no hand-written figures; every number is read from that JSON.
3. **What is not in the committed data is shown as not recorded.** Repair feedback is committed as
   `stage.code` only; file and line are not, so the UI says "not recorded" rather than inventing them.
4. **v0.6 endpoints do not exist yet.** Policy, audit and approvals use typed fixtures shaped like the
   v0.6 plan (section 3 and 6), marked `FIXTURE` in code and on screen, behind `src/api/policy.ts`
   (swapping to REST is a change to that one file). Fixture rows carry no metrics.
5. **Live mode scope.** Health, mapping review (`GET /mapping-runs/{id}`, `/mappings`) and an
   integration's pipeline state (`GET /integrations/{id}`, versions, gate, sandbox runs). Results and
   repair attempts have no REST endpoint, so live mode shows the recorded data with the same label.
6. **Lazy loading.** Monaco (local ESM build, Python and JavaScript grammars only, no CDN) and React Flow
   are separate chunks loaded by their screens. Hash routing, so the static build works on any subpath.
7. **Deploy config only.** `frontend/vercel.json`; `base: './'` keeps the build GitHub Pages compatible.

## Screens

Overview (60-second summary), Pipeline (React Flow, state per selected unit, detail panel), Repair
(attempt timeline, Monaco diff of consecutive replies, feedback codes, guard trips, terminal state),
Results (D, L1, L2, L1R, L2R per unit; READY-but-incorrect distinct; exposure tags; N = 1 note), Review
gate (as-proposed blocked reasons and the S1 proposals), Policy and audit (fixtures).

## Design system

CSS custom properties for colour, type, spacing, radii and motion; dark default, light option, both
checked for WCAG AA on text; IBM Plex Sans Condensed and IBM Plex Mono, self-hosted. Command palette
(Ctrl/Cmd+K), number keys for screens, visible focus rings, skeleton, empty and error states, layout down
to 768 px, `prefers-reduced-motion` honoured.

## Exit criteria (stop if one fails)

`tsc -b` strict, ESLint clean, Vitest (screens plus the drift test) green, Playwright demo smoke (every
screen, no console error) green with screenshots in `docs/img/`, Monaco and React Flow absent from the
entry chunk, Lighthouse performance and accessibility measured on the built demo and reported as
measured, frozen v0.4 paths unchanged against `fcd86ff`, frontend CI job green.
