# v0.7-ui plan (redesign)

Branch `ui/v0.7`, on top of the first v0.7 commit (`7086629`). Changes stay in `frontend/` (code, generated
data, deploy config), `docs/` (this plan, `docs/img/`) and the README UI section. No backend, bench or
sandbox change, no model call, no tag, no deploy, no history rewrite.

## What stays

The data layer of the first cut is kept: `scripts/demo-data.ts` builds `src/data/*.generated.json` from
committed files only, the Vitest drift test rebuilds it and fails on any difference, `src/api/policy.ts` is
the one adapter in front of the policy fixture, and `src/api/rest.ts` stays the live-mode client.

## What changes

1. **Two surfaces.** Hash routes: `#/` is a landing page; `#/app/<screen>` is the product shell. Old
   `#/<screen>` links redirect. Landing, shell and every screen are separate lazy chunks; Monaco and React
   Flow load only with their screens.
2. **More of the landing page is generated.** The generator also reads `README.md`: the repository URL
   (CI badge link), the design-principles table (Guarantees, each with the files that enforce it), the
   status table (Roadmap) and the honest-findings headlines. The drift test covers them like the results.
   Counts on the landing page (D 3/3, L1 0/3, L2 0/3, L1R 3/3 with 2 correct and 1 READY-but-incorrect,
   L2R 0/3, N=1) are computed from the units, never typed. The existing "no hand-typed figures" test is
   extended to the landing page and shell.
3. **Preview, not fixture, on screen.** v0.6 policy, audit and approvals stay fixtures in code
   (`FIXTURE` comments, `src/fixtures/`), shown as "Preview" in the UI, behind `src/api/policy.ts`.
4. **Shell.** Collapsible sidebar, breadcrumbs, a run selector (v0.5 fixed-start repair or v0.4 one-shot
   codegen; it scopes the pipeline picker, repair view, results emphasis and the badge), the persistent
   recorded-run badge, command palette (Ctrl/Cmd+K) over screens and units, keyboard shortcuts with a help
   dialog (`?`).
5. **Screens.** Overview; Pipeline (React Flow, state-coloured nodes, animated traversed path, detail
   drawer); Repair (attempt timeline 0-3 with layout animation, Monaco diff, structured feedback, guards,
   terminal state); Results (per unit READY / oracle / attempts / tokens incl. reasoning, READY-but-incorrect
   hatched and labelled, exposure tags); Review gate; Policy and audit (Preview).
6. **Motion** (`motion` 13.3.0, loaded through `LazyMotion` so its features are a separate chunk): one
   token file for durations and easings; page transitions; scroll reveal on the landing page; staggered
   lists; count-ups only on generated numbers; shared-layout timeline; CSS shimmer skeletons. Under
   `prefers-reduced-motion` every transform is dropped, count-ups show the final value, nothing waits on
   an animation.
7. **Design system.** Tokens for colour, type, spacing, radii, elevation and motion; dark default with a
   light option; Bricolage Grotesque (display) with IBM Plex Sans (text) and IBM Plex Mono (data), all
   self-hosted. Components: button, card, table, badge, tabs, dialog, toast, tooltip, skeleton, empty and
   error states. The contrast test checks every text token on every surface in both themes (WCAG AA).
8. **Deploy config only.** `frontend/vercel.json`, and a GitHub Pages workflow kept inert under
   `frontend/deploy/` with `public/.nojekyll`; `base: './'` makes the build path-independent.

## Exit criteria (stop if one fails)

`tsc -b` strict, ESLint clean, Vitest green (screens, drift, contrast, secrets, no-assistant-mention),
`check:bundle` (Monaco and React Flow not reachable from the entry), Playwright demo smoke green (landing
loads, CTA reaches the app, every screen, palette and help dialog open, no console error) with screenshots
written to `docs/img/`, Lighthouse performance and accessibility measured on the built landing page and one
app screen and reported as measured, standing checks clean, frontend CI job green.
