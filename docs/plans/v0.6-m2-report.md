## Design points that matter

* **The audit log is independent of the business transaction.** Each append opens its own short
  transaction, takes a per-chain advisory lock, reads the chain head, takes the next sequence number and
  inserts. A tool call that fails and rolls back still leaves its audit events, and a long repair run
  never holds the lock.
* **Chains.** Events carry a chain name (production uses `main`). Each test uses a private chain so a
  deliberately tampered chain does not affect another test.
* **Hash.** Each event's hash covers the chain, sequence number, previous hash, timestamp (microseconds,
  UTC), session, type, tool, principal, call id, policy hash and payload. Payloads are redacted before
  they are hashed and stored, and floats are refused because their text form is not stable.
* **Approvals** are bound to the tool, the hash of the arguments without the approval id, and the policy
  hash; they are single use (a conditional `UPDATE ... RETURNING` decides the winner), they expire by the
  injected clock, and an expired `PENDING` or `APPROVED` is reported as `EXPIRED` without a write.
* **Attributes**: a system with no record is `unknown` environment and `unclassified` data, the most
  restrictive values. Across the systems a call involves, the most restrictive value wins.

## Disclosed limits

* **Tail truncation is not detected.** Removing the last events of a chain leaves a shorter valid chain,
  because there is no anchor outside the database. A test states this limit instead of hiding it.
* **The trigger can be switched off by the database owner.** The tamper tests do exactly that to show that
  the hash chain still catches the edit. The hash chain, not the trigger, is the defence against that
  actor; the trigger is the defence against the application and ordinary SQL.
* **Counters** (model calls, sandbox runs) will be derived from `CHARGE` events by session in M3; a server
  restart is a new session and starts from zero.
* The REST read routes are open like the rest of the local API, as decided. Only the two writes need
  the approver token.
