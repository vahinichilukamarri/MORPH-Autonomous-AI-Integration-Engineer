# v0.5 M1 report

M1 scope: the pure repair modules (no LangGraph, no model, no database) and their tests, the
provider-layer `finish_reason`, and the smoke test promoted from prototype to committed code with
positive and negative controls. **No model was called.** Numbers below are counts from test runs on
this machine (Windows, Docker Desktop); CI results are in the reply that accompanies this report.

## 1. What was added

| Module (`backend/app/repair/`) | Purpose |
|---|---|
| `feedback.py` | `Feedback` and `FeedbackItem`: sorted by stage, file, line and code; deduplicated; at most 8 items and 1,200 characters of item text; messages at most 200 characters; POSIX bundle-relative paths; configured secret values and opaque 40-character-or-longer runs removed; a `SECRET_LITERAL` finding is described by its origin (edge record index, field, string length) and never by the literal. Items for the validator, the three gate stages, the guards, the generated tests and the smoke test. |
| `failures.py` | Which failures use an attempt and which pause. A reply cut off at the output limit (`finish_reason=length`), an empty reply and a non-JSON reply are **model failures** with a distinct `TRUNCATED` / `EMPTY_OUTPUT` / `INVALID_JSON` item. Provider errors, 429s, a sandbox that did not start and `LimitsNotEnforced` are infrastructure. A missing replay is **not** infrastructure. |
| `guards.py` | G1 to G5 enforced, G6 and G7 shadow-only (reported, never reject), no-op detection against **any** earlier attempt's hash, and `evaluate_guards` to run them together. |
| `smoke.py` | The repair-mode smoke test, run in the existing sandbox as a `python -c` argument. |

Provider layer: `CallMetadata.finish_reason` (Groq `finish_reason`, Ollama `done_reason`), carried
through the record, cache and replay paths, stored in `llm_calls.finish_reason` (migration `0007`).
All new fields default to `None`; the v0.4 replay test is unmodified and passes.

## 2. Smoke test: promoted from the M0 prototype

What changed from the prototype, and one correction to the M0 report:

- **Correction.** The M0 report said the fake clients take their page-key names from the bundle's
  `manifest.json`. For an **L2 bundle the manifest strategy is empty** (`generate_package` returns
  `strategy={}` when `sync_source` is given), so the caller passes the shape instead: the
  strategy D derives for the same contract (`derive_strategy`), which exists for every condition.
- The fake source now paginates honestly (`page`/`size` from the contract's parameter names), so a
  module that pages with a different size is not fed the same records forever.
- Pass means: the entry point imports, finishes inside the time limit (the sandbox limit is cut to
  **20 s** for this run by a second `SandboxRunner` with a shorter `timeout_s`; every other limit is
  identical), prints a last line that is a JSON object with `status`, `records` and `requests`, and
  the run status is not `FATAL` (exit code 0 or 3). It asserts nothing about record contents,
  outcomes or request counts.
- Result codes: `OK`, `SETUP`, `IMPORT_ERROR`, `RAISED`, `NO_REPORT`, `BAD_SHAPE`, `RUN_FATAL`,
  `TIMEOUT`, `CRASH`, and the sandbox outcomes; `START_FAILED` is flagged `infra=True` so it pauses
  instead of failing the attempt.
- No sandbox containment change: same image, same mount, same flags.

## 3. Guards: false positives found and what they were

Every guard was run against D's bundle for S1, S3 (backend tests) and S1, S3, S4 (bench test, CI),
against the runtime's own sync engine (`morph_runtime/sync.py`, trusted reference), and against the
positive control. **Result: zero findings of any kind**, enforced or shadow, on all of them.

One false positive was found on the way and fixed **in the input definition, not by weakening the
guard**: G5 first reported `mapped fields written nowhere: customer_id` on D's S3 bundle. In S3 the
target assigns `customer_id` itself, so it is mapped (to find the record) but never written. G5's
`included` input is now defined as the approved mappings the contract lets a create or update request
carry (`names & plan.target.writable`); the plan's G5 row says so. A guard that rejects D is a bug,
which is what the test is there to find.

G6 and G7 were exercised on synthetic code that trips both: they report, `rejected` stays false, and
the positive control's bundle still counts as clean.

## 4. Isolation (`tests/repair/test_isolation.py`)

- The import graph reachable from `app.repair` (followed through `app/**`) contains no
  `morph_bench`, `bench`, `oracle` or `tests` import, and no file in it mentions `answer_key` or
  `morph_bench`; none of the live providers (`app.llm.groq`, `ollama`, `factory`) or `httpx` is
  reachable, so repair code cannot construct a provider and a fixed-start seed can only arrive as an
  injected replay.
- No `importlib`, `runpy`, `imp`, `pkgutil`, `__import__`, `exec`, `eval`, `compile` or `.import_module` in
  `app/repair/**`. The scanners are tested against code that violates them.
- No string in `app/repair/**` (docstrings excepted) names a grading or fixture path.
- The pure modules open no file and read no environment variable (they import neither `os` nor
  `tempfile`); `pathlib` appears only in `smoke.py`, to type the bundle directory.
- The pure modules import no LangGraph or LangChain package.
- A missing replay record raises `ReplayMissError`, which `is_infrastructure_error` refuses to
  treat as a pause. The end-to-end version (a fixed-start unit with a missing record aborts and a
  live provider is never called) needs the graph and arrives with M2.

## 7. Limits worth knowing

- READY under repair still does not mean correct. The smoke test cannot see a wrong field, a wrong
  outcome or a wrong request count; the pre-registered L1 S3 prediction stands.
- The smoke test treats a `FATAL` run as a failure. A correct module that aborts on the fakes'
  data (for example by reporting contract drift) would fail it; the fakes serve complete records
  taken from the generated test cases, so this is not expected for a correct module.
- G4 counts `Any`, `cast(...)` and `object` annotations; it cannot tell a justified `Any` from a
  lazy one, which is why it only compares against the previous attempt.
